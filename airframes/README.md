# Airframes — функциональные модули дрона

Каталог `airframes/` содержит опциональные функциональные модули полётной
платформы. Каждый модуль представляет собой автономный блок, подключаемый к
системе независимо от остальных: UWB-позиционирование, 3D-лидар, роевое
взаимодействие (swarm), нанесение граффити и иные подсистемы, добавляемые по
мере развития платформы.

Архитектурный принцип: базовый стек (управление полётом, камера, одометрия)
собирается и запускается всегда; модули данного каталога являются
опциональными расширениями и активируются только для тех сборок, где они
требуются.

## Структура модуля

Модуль — это самостоятельный ROS 2 пакет (либо git-подмодуль, содержащий
такой пакет), размещённый в подкаталоге `airframes/<module>/`.

Пример действующего модуля:

- **`ros-uwb/`** — драйвер UWB-модуля (Ultra-Wideband) для высокоточного
  позиционирования в помещении по радиометкам. Публикует результаты
  дальнометрии (`/uwb/result`) и данные о соседних узлах (`/uwb/peer_info`).
  Полное описание — [`ros-uwb/README.md`](ros-uwb/README.md).

Каждый модуль обязан предоставлять:

1. **Пакет ROS 2** — собирается в составе рабочего пространства командой
   `colcon build`.
2. **Launch-файл** — `launch/<module>.launch.py` внутри пакета. Подключение
   выполняется исключительно через корневой launch-файл
   `main_package/launch_system/launch/full_system_real.launch.py`; прямой
   запуск отдельных нод в обход этого файла не предусмотрен.
3. **Флаг активации** — переменную окружения `ENABLE_<MODULE>` (например
   `ENABLE_UWB`, `ENABLE_LIDAR`, `ENABLE_SWARM`, `ENABLE_GRAFFITI`). При
   выключенном флаге модуль не запускается, даже если его код включён в образ.

## Механизм активации

Активация модуля выполняется по следующей цепочке конфигурации:

```
image_builder/types.yaml    →  runtime_env: ENABLE_<MODULE>=1   (тип addon)
        ↓  записывается на устройство при первичной инициализации
device .env                 →  ENABLE_<MODULE>=1
        ↓  считывается контейнером при старте
full_system_real.launch.py  →  if ENABLE_<MODULE>: include launch/<module>.launch.py
```

Флаг `ENABLE_*` задаётся не в исходном коде, а в окружении контейнера, которое
формируется сборщиком образа на основе активных типов-addon. Значения флагов,
прописанные непосредственно в launch-файле, служат резервными (fallback) и
используются только при ручном запуске через `docker run`.

Детали системы типов и сборки образа приведены в `image_builder/README.md`.

## Реестр модулей

| Модуль | Каталог | Флаг | Статус |
|--------|---------|------|--------|
| UWB-позиционирование | `ros-uwb/` | `ENABLE_UWB` | реализован |
| 3D-лидар | — | `ENABLE_LIDAR` | планируется |
| Swarm (рой) | — | `ENABLE_SWARM` | планируется |
| Graffiti | — | `ENABLE_GRAFFITI` | планируется |
| Прочие расширения | `airframes/<module>/` | `ENABLE_<MODULE>` | по мере разработки |

## Порядок добавления нового модуля

1. Разместить ROS 2 пакет в `airframes/<module>/` (обычный пакет либо
   git-submodule).
2. Реализовать внутри пакета launch-файл `launch/<module>.launch.py`.
3. Подключить launch-файл в `full_system_real.launch.py` под условием флага
   `ENABLE_<MODULE>`.
4. Описать тип-addon в `image_builder/types.yaml` (с директивой
   `runtime_env: ENABLE_<MODULE>=1`), разместить его скрипты и compose-оверлеи
   в `scripts/types/<type>/`, добавить соответствующую запись в корневой
   `web-builder.yaml`.
5. Задокументировать модуль в `README.md` его каталога: назначение,
   публикуемые топики и сервисы, требования к аппаратной части.

> Документация и комментарии в репозитории ведутся на русском языке —
> придерживайтесь этой конвенции при добавлении новых модулей.
